# 05 · API

The app reads and writes most data **directly in Supabase** (protected by RLS, see [Architecture §3](03-architecture.md#3-client-data-flow-local-first)). The HTTP endpoints below exist for clients that can't use Supabase directly (Shortcuts, the service worker) and for work that needs secrets.

## 1. Conventions

- **Base URL:** `https://<app-domain>`. JSON request and response bodies, UTF-8.
- **Versioning:** the Shortcuts API lives under `/api/v1`. Breaking changes go to `/api/v2`, because shortcuts already installed on phones can't be updated automatically.
- **Language:** server-generated text (`speech`, `message`, notification text) uses the profile language. `?lang=es|en` overrides it.
- **Dates:** `YYYY-MM-DD`, always habit days (`R-DAY`).
- **Every `/api/v1` response has a `speech` field:** a short sentence in the user's language for Siri to say, so shortcuts don't need logic to build sentences.
- **Errors:**

  ```json
  {
    "error": {
      "code": "habit_not_found",
      "message": "No habit matches \"medit\"",
      "speech": "No encontré ningún hábito llamado medit."
    }
  }
  ```

  | HTTP | `code` | When |
  |---|---|---|
  | 401 | `unauthorized` | Missing, invalid or revoked token / session |
  | 403 | `forbidden_scope` | Token lacks the scope |
  | 404 | `habit_not_found`, `nothing_to_undo` | |
  | 409 | `ambiguous_habit` | The query matches several habits; the response includes `choices` |
  | 422 | `validation_error`, `outside_edit_window`, `not_allowed_for_habit`, `skip_limit_reached` | Bad input, or a rule from `R-CHK` / `R-SKIP` |
  | 429 | `rate_limited` | Includes `Retry-After` |
  | 500 | `internal` | |

## 2. Shortcuts API (v1)

**Authentication:** `Authorization: Bearer ht_<token>`. The token is created in *Settings → Siri & Shortcuts* and shown only once. Scopes: `habits:read`, `checkins:write`, `health:write`.
**Rate limit:** 60 requests/min per token.
**Optional header:** `X-Shortcut-Version: 1.0`. If it's older than the current recipe, the `speech` of the response adds "A new version of the shortcut is available" once per day.

### `GET /api/v1/today`

Today's habits, ready for Shortcuts' *Choose from List*. Scope `habits:read`.

| Query param | Values | Default |
|---|---|---|
| `include` | `pending`, `all` | `pending` |
| `routine` | routine ID or `morning` / `evening` | all routines |

```json
{
  "date": "2026-10-20",
  "score": 56,
  "pending_count": 3,
  "choices": {
    "🧘 Meditar · Mañana": "6f1c2e7a-…",
    "📖 Leer (10/20) · Mañana": "a2b9…",
    "💧 Agua (6/8)": "c3d4…"
  },
  "items": [
    { "id": "6f1c2e7a-…", "name": "Meditar", "routine": "Mañana", "kind": "boolean",
      "state": "pending", "value": null, "target": null, "streak": 11 }
  ],
  "speech": "Te quedan 3 hábitos: Meditar, Leer y Agua."
}
```

`choices` is an object on purpose. When *Choose from List* receives a dictionary, it shows the **keys** (readable labels). *Get Dictionary Value* with the chosen key then returns the habit ID.

### `POST /api/v1/check-ins`

Log a habit. Scope `checkins:write`. The source is recorded as `siri`.

```json
{
  "habit_id": "6f1c2e7a-…",
  "action": "log",
  "date": "today"
}
```

| Field | Type | Notes |
|---|---|---|
| `habit_id` | UUID | Either this or `query` |
| `query` | string | Habit name or alias, matched fuzzily (`R-CHK`, `FR-SIR-3`) |
| `action` | `log` (default), `complete`, `increment`, `set_value`, `skip` | `log` = complete a boolean habit, or add `increment_step` to a measurable one |
| `amount` / `value` | number | For `increment` / `set_value` |
| `reason` | `sick`, `travel`, `rest`, `other` | For `skip` |
| `date` | `today` (default), `yesterday` | Inside the edit window |
| `op_id` | UUID | Optional idempotency key; generated by the server if missing |

**200**

```json
{
  "check_in": { "habit_id": "6f1c2e7a-…", "date": "2026-10-20", "state": "done", "value": null, "source": "siri" },
  "habit": { "name": "Meditar", "streak": 12, "milestone": null },
  "day": { "score": 75, "pending_count": 2, "routine_pending": 1 },
  "speech": "Listo, Meditar ✅. Llevas 12 días seguidos. Te queda 1 hábito de la mañana."
}
```

- Already done (boolean or flexible): **200**, nothing changes, `"speech": "Meditar ya estaba hecho hoy."`.
- Measurable: `"speech": "Agua: 7 de 8 vasos."`.
- Last pending habit of the day: `"speech": "¡Día perfecto! 🎉 Completaste todo."`.
- Milestone: `habit.milestone = 30` and the speech mentions it.
- **409 `ambiguous_habit`** includes `choices` with the candidates, so the shortcut can ask again.

### `POST /api/v1/check-ins/undo`

Undo the user's last check-in operation of today, from any source. Scope `checkins:write`. Body: `{}`.

```json
{ "undone": { "habit": "Meditar", "op": "complete" }, "speech": "Deshice Meditar." }
```

**404 `nothing_to_undo`** if there's nothing from today to undo.

### `GET /api/v1/summary`

"How am I doing?". Scope `habits:read`.

```json
{
  "date": "2026-10-20",
  "score": 56,
  "done": 5,
  "total": 9,
  "pending": ["Leer", "Agua", "Diario"],
  "weekly": [{ "name": "Gimnasio", "done": 2, "target": 4 }],
  "best_streak": { "name": "Meditar", "days": 12 },
  "speech": "Vas 56%. Te faltan Leer, Agua y Diario. Gimnasio: 2 de 4 esta semana."
}
```

### `POST /api/v1/health`

Send Apple Health daily totals. Scope `health:write`. Sent by the "Sync Health" shortcut ([Integrations §2](06-integrations.md#2-apple-health)).

```json
{
  "metrics": [
    { "metric": "steps",            "date": "2026-10-20", "value": 6234 },
    { "metric": "steps",            "date": "2026-10-19", "value": 10450 },
    { "metric": "exercise_minutes", "date": "2026-10-20", "value": 32 },
    { "metric": "workouts",         "date": "2026-10-20", "value": 1 }
  ]
}
```

- `metric` is one of the `health_metric` values. `date` must be within the last 7 days. `value ≥ 0`. At most 50 items.
- Metrics that none of the user's habits use are discarded (`R-HLT-5`).
- Rules from `R-HLT-3` are applied in the same transaction.

```json
{
  "accepted": 3,
  "ignored": 1,
  "completed": [{ "habit": "Caminar 5.000 pasos", "date": "2026-10-19" }],
  "speech": "Salud sincronizada. Completé Caminar 5.000 pasos de ayer."
}
```

## 3. App endpoints (user session)

| Method | Path | Body / query | Response |
|---|---|---|---|
| `POST` | `/api/tokens` | `{ "name": "My iPhone" }` | `{ "id", "token", "prefix" }`. The token is shown only here |
| `DELETE` | `/api/tokens/:id` | | `204`. Sets `revoked_at` |
| `POST` | `/api/push/subscriptions` | `{ "endpoint", "keys": { "p256dh", "auth" }, "platform", "device_label" }` | `201`. Upsert by `endpoint` |
| `DELETE` | `/api/push/subscriptions` | `{ "endpoint" }` | `204` |
| `POST` | `/api/push/test` | | `202`. Sends a test notification to all the user's devices |
| `POST` | `/api/notifications/snooze` | `{ "habitId", "date", "minutes": 15 \| 30 \| 60 }` | `201 { "sendAt" }`. "Remind me later" from the app, for iPhone (`FR-NTF-8`). At most 3 waiting per habit and day |
| `GET` | `/api/calendar/google/connect` | | `302` to Google's consent screen, with `state` bound to the session |
| `GET` | `/api/calendar/google/callback` | `?code&state` | `302` to `/settings/integrations?calendar=connected` |
| `POST` | `/api/calendar/google/disconnect` | `{ "delete_calendar": false }` | `204` |
| `POST` | `/api/calendar/google/resync` | | `202`. Queues `full_resync` |
| `GET` | `/api/export` | `?format=json` or `?format=csv` | File download |
| `DELETE` | `/api/account` | `{ "confirm": "DELETE" }` (or `"BORRAR"`) | `204`. Revokes Google access, deletes the auth user (cascades) |

## 4. Service-worker and internal endpoints

### `POST /api/notifications/action`

Called by the service worker when a notification button is pressed. It doesn't use a session: the notification carries a signed **action token** ([Architecture §10](03-architecture.md#10-security-and-privacy)).

```json
{ "token": "eyJ…", "action": "done" }
```

`action`: `done` or `snooze` (with `"minutes": 15`). Response: `{ "ok": true }`. The token can only be used once.

### `POST /api/internal/tick`

Called every minute by `pg_cron`. Header `x-cron-secret`. Runs the steps in [Architecture §5](03-architecture.md#5-scheduler). Response: `{ "planned": 12, "sent": 40, "suppressed": 7, "calendar_jobs": 3, "ms": 1840 }`.

## 5. Database functions (RPC)

### Called by the app (role `authenticated`)

| Function | Does |
|---|---|
| `apply_check_in_op(op_id uuid, habit_id uuid, local_date date, op text, payload jsonb, source check_in_source) → check_ins` | The only way to write check-ins. Checks ownership, the edit window, the habit's kind and schedule (`R-CHK`), the skip limit (`R-SKIP`), derives the state (`R-STATE`), writes `check_in_events` with `prev_state`, and is idempotent on `op_id`. `security definer`, `search_path = ''` |
| `undo_op(op_id uuid) → check_ins` | Restores `prev_state` of that operation. Used by the Undo toast |
| `undo_last_op() → jsonb` | Undoes the user's last operation of today that hasn't been undone |

### Server only (role `service_role`; `execute` revoked from `anon` and `authenticated`)

| Function | Does |
|---|---|
| `srv_verify_api_token(hash bytea) → (user_id, token_id, scopes)` | Checks the token isn't revoked and updates `last_used_at` |
| `srv_rate_limit(key text, max int, window interval) → boolean` | Fixed-window counter on `rate_limits` |
| `srv_apply_check_in_op(user_id, …)` / `srv_undo_last_op(user_id)` | The same as the app functions, for a given user (Shortcuts API, notification buttons) |
| `srv_match_habit(user_id uuid, query text) → setof (habit_id, name, score)` | Trigram similarity on `srv_normalize(name)` and aliases; candidates with score ≥ 0.3, best first |
| `srv_apply_health_metrics(user_id uuid, metrics jsonb) → jsonb` | Upserts `health_metric_days` and applies `R-HLT-3` |
| `srv_claim_due_notifications(max int) → setof scheduled_notifications` | Locks due rows with `FOR UPDATE SKIP LOCKED` and marks them `sending` |
| `srv_claim_profiles_to_plan(max int) → setof (user_id, today)` | Users with `plan_dirty` or `planned_through` before their tomorrow; clears `plan_dirty` as it claims them |
| `srv_replace_plan(user_id, from date, through date, rows jsonb) → int` | Atomically deletes the user's pending notifications from `from` on (not tests or snoozes), inserts `rows` with `on conflict (dedupe_key) do nothing`, sets `planned_through` |
| `srv_claim_calendar_jobs(max int) → setof calendar_sync_jobs` | The same for calendar jobs, coalescing duplicates |
| `srv_user_today(user_id uuid) → date` | `R-DAY-2` |

**Matching a habit by voice** (`srv_match_habit`):

1. Normalize the query: lowercase, no accents, no filler words ("el", "la", "my", "the").
2. Exact match on the name or an alias → that habit.
3. Otherwise trigram similarity against names and aliases, among active habits. One candidate ≥ 0.3, or a best candidate at least 0.15 ahead of the second → that habit.
4. Several close candidates → `409 ambiguous_habit` with `choices`. None → `404 habit_not_found`.
